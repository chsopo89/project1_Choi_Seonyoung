네트워크 엔지니어 관점에서 답변드립니다.

네트워크 통신(Ping)이 정상이고 정책 및 서버 설정이 올바름에도 불구하고 **로컬 로그가 쌓이지 않고 원격 로그 서버로도 전송되지 않는 현상**은, 통신 문제보다는 **FortiGate 내부의 로그 처리 데몬(Daemon) 오류, 리소스 고갈(Conserve Mode), 저장소 이상, 또는 소스 IP 바인딩 문제**일 가능성이 매우 높습니다.

단계별 점검 순서와 확인 항목은 다음과 같습니다.

---

### [추정 원인]
1. **로그 처리 데몬(`miglogd`) 교착/다운**: 로그 생성을 담당하는 프로세스가 다운되었거나 멈춘 경우.
2. **시스템 보호 모드(Conserve Mode) 진입**: 메모리 사용량이 극도로 높아 로그 생성을 장비 스스로 중단한 경우.
3. **로컬 로그 디스크 오류/가득 참**: 디스크 파일시스템 오류 또는 가득 참으로 인해 로컬 저장 및 큐(Queue) 처리가 정지된 경우.
4. **Syslog 소스 IP(Source-IP) 미지정 또는 불일치**: Ping은 기본 라우팅을 타지만, 로그 패킷은 올바르지 않은 소스 IP로 나가는 경우.

---

### [단계별 점검 순서 및 확인 항목]

#### 1단계: 메모리 보호 모드(Conserve Mode) 및 리소스 점검
장비의 메모리 사용량이 늘어나 Conserve Mode에 진입하면 FortiGate는 시스템 안정성을 위해 가장 먼저 로그 기록 기능을 끕니다.
* **확인 명령:**
  ```text
  get system performance status
  ```
* **점검 항목:** 메모리 사용율이 80%~88% 이상인지 확인합니다. Conserve Mode 상태라면 무의미한 프로세스를 정지하거나 장비 재부팅/리부팅을 고려해야 합니다.

---

#### 2단계: 로그 프로세스(`miglogd`) 상태 확인 및 재시작
FortiGate의 모든 로그 생성 및 전송은 `miglogd` 데몬이 담당합니다. Ping이 되어도 이 데몬이 멈춰있으면 로그가 전혀 발생하지 않습니다.
* **확인 명령:**
  ```text
  diagnose sys process pidof miglogd
  ```
* **조치 방법:** PID가 조회되지 않거나 데몬이 응답하지 않을 경우, 데몬을 강제 재시작하여 복구시킵니다.
  ```text
  fnsysctl killall miglogd
  ```
  *(재시작 후 몇 분 뒤 로그가 다시 쌓이는지 확인합니다.)*

---

#### 3단계: 로컬 디스크 및 로그 저장 설정 상태 점검
로컬 로그 저장이 비활성화되어 있거나 디스크에 문제가 생기면 버퍼가 막혀 원격 로그 전송까지 영향을 줄 수 있습니다.
* **확인 명령:**
  ```text
  get log disk setting
  diagnose sys logdisk status
  ```
* **점검 항목:** 
  * `status`가 `enable`로 되어 있는지 확인
  * 디스크 상태가 `Need Format` 또는 오류 상태인지 확인 (필요 시 디스크 포맷 진행)

---

#### 4단계: Syslog 설정 및 Source IP 바인딩 확인
Syslog 설정에서 전송 상태가 활성화되어 있는지, 바인딩된 IP가 정확한지 확인합니다.
* **확인 명령:**
  ```text
  get log syslogd setting
  ```
* **점검 항목:**
  * `status` : `enable` 여부
  * `mode` 및 `port` : Syslog 서버가 수신하는 포트(예: UDP 514)와 일치하는지 확인
  * `source-ip` : 로그 서버로 향하는 인터페이스의 IP로 정확히 지정되어 있는지 확인 (미지정 시 의도치 않은 인터페이스 IP로 나가 수신 거부될 수 있음)

---

#### 5단계: 패킷 스니핑(Packet Capture)을 통한 전송 여부 확인
FortiGate CLI에서 로그 서버로 패킷을 실제로 내보내고 있는지 실시간으로 확인합니다.
* **확인 명령:**
  ```text
  diagnose sniffer packet any 'host <로그서버IP> and port 514' 4
  ```
* **결과 해석:**
  * **패킷이 출력되지 않음:** FortiGate 내부(데몬/설정)에서 로그 패킷을 생성하지 못하고 있음 $\rightarrow$ 6단계 진행
  * **패킷이 나가는 것이 확인됨:** FortiGate는 정상 송신 중이나, 중간 네트워크 장비(ACL) 또는 로그 서버 측 방화벽/Syslog 서비스 문제임.

---

#### 6단계: 로그 데몬 실시간 디버깅 (최종 점검)
상기 점검 후에도 원인을 찾을 수 없다면 `miglogd` 디버그를 통해 내부 에러 메시지를 확인합니다.
* **확인 명령:**
  ```text
  diagnose debug application miglogd -1
  diagnose debug enable
  ```
* **점검 항목:** 화면에 출력되는 에러 로그(예: Buffer full, Connection refused, Disk failure 등)를 확인하여 원인을 특정합니다.
* **주의 사항:** 점검 완료 후 반드시 디버그를 끕니다.
  ```text
  diagnose debug disable
  ```

---

### [요약]
대부분의 경우 **1단계(Conserve Mode)** 혹은 **2단계(`miglogd` 데몬 먹통)**에서 원인이 발견됩니다. 데몬 재시작(`fnsysctl killall miglogd`)과 `source-ip` 바인딩 점검을 우선적으로 수행하는 것을 권장합니다.
