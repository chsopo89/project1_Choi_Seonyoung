증상상 우선순위는 **STP 불일치 또는 중복 L2 경로에 의한 루프**입니다. LLDP 인식과 링크 Up은 물리·인접성만 확인할 뿐, VLAN 전달과 루프 방지는 보장하지 않습니다.

## 1. 먼저 루프를 안정화

1. 문제 구간의 신규 링크 또는 이중 연결 중 하나를 차단합니다.
2. 모든 경로를 동시에 열어 둔 상태에서 계속 시험하지 않습니다.
3. MAC 주소가 여러 포트에서 반복적으로 이동하는지, 브로드캐스트·멀티캐스트·unknown unicast가 급증하는지 확인합니다.
4. 인터페이스 입력/출력 오류, discard, storm-control 동작 여부와 MAC flap 로그를 확인합니다.

특히 다음 형태를 확인해야 합니다.

- Cisco와 Juniper 사이에 물리 링크가 2개 이상인데 한쪽만 LAG/Port-Channel로 구성됨
- Cisco의 Port-Channel과 Juniper의 LAG 구성원 또는 해시 설정이 불일치함
- 별도의 액세스 포트 또는 다른 스위치 경로를 통해 두 장비가 다시 연결됨
- STP가 한쪽에서 비활성화되었거나, BPDU가 필터링·차단됨

**STP를 임시로 양쪽 모두 끄는 방식은 피해야 합니다.** 원인 확인 전에는 한 경로만 활성화하는 것이 안전합니다.

## 2. VLAN별 단방향 통신 여부 확인

통신되지 않는 VLAN과 정상 VLAN을 각각 비교합니다.

### 양쪽 장비에서 확인할 항목

- 해당 VLAN이 장비에 실제로 생성되어 있는가
- 트렁크 포트의 허용 VLAN 목록에 포함되어 있는가
- 트렁크 양 끝의 태깅 방식이 일치하는가
- VLAN이 중간 경로의 모든 트렁크에서 허용되어 있는가
- 액세스 포트가 올바른 VLAN에 속하는가
- VLAN 삭제, shutdown, pruning 상태가 아닌가

Cisco에서는 `show interfaces trunk`, `show vlan` 계열 출력으로 확인하고, Juniper에서는 `show vlans`, `show ethernet-switching interfaces` 및 해당 포트 설정을 확인합니다. 정확한 명령은 장비 모델과 Junos/IOS 계열에 따라 달라질 수 있습니다.

### 특히 Native VLAN 확인

Cisco 트렁크의 native VLAN은 기본적으로 untagged로 전달될 수 있습니다. Juniper는 설정에 따라 native VLAN을 별도로 지정하거나 VLAN 태그를 요구할 수 있습니다.

따라서 다음을 비교해야 합니다.

- native VLAN ID
- native VLAN이 실제로 필요한지
- 양쪽 모두 해당 VLAN을 untagged로 처리하는지
- 한쪽은 native로 보내고 다른 쪽은 tagged로 기대하지 않는지

가능하면 상호 연결 구간에서는 관리 목적이 아닌 native VLAN 사용을 최소화하고, 양쪽의 tagging 정책을 명확히 동일하게 구성합니다.

## 3. STP 상호운용성 확인

Cisco가 PVST+/Rapid-PVST+이고 Juniper가 RSTP 또는 MSTP인 경우, VLAN별 STP 동작과 BPDU 상호운용성을 확인해야 합니다.

확인할 항목은 다음과 같습니다.

- 양쪽의 STP 모드
- 루트 브리지와 루트 포트가 의도한 위치인지
- 해당 인터페이스가 forwarding인지 blocking/discarding인지
- BPDU가 실제로 송수신되는지
- BPDU filter, BPDU guard, edge/portfast 설정이 트렁크에 적용되어 있지 않은지
- MST를 사용하는 경우 region name, revision, VLAN-to-instance 매핑이 일치하는지

Cisco에서는 `show spanning-tree` 및 인터페이스별 STP 상태를, Juniper에서는 `show spanning-tree` 계열 명령과 설정을 확인합니다. STP 모드가 서로 다른 경우 “링크가 정상”이어도 VLAN별로 차단 상태가 예상과 다를 수 있으므로, 운영 표준을 하나로 정한 뒤 맞추는 것이 좋습니다.

## 4. MAC 학습과 경로 확인

문제 VLAN의 단말 MAC 주소가 어느 포트에서 학습되는지 양쪽에서 비교합니다.

- 같은 MAC이 짧은 시간에 두 포트 사이를 반복 이동하는가
- 문제 VLAN의 MAC이 트렁크에서 전혀 학습되지 않는가
- MAC이 잘못된 액세스 포트에 나타나는가
- ARP는 보이지만 응답 트래픽이 다른 VLAN 또는 다른 경로로 나가는가

MAC flap이 관측되면 VLAN 허용 목록보다 먼저 중복 경로와 LAG/STP 구성을 조사해야 합니다.

## 5. 안전한 이전 순서

1. **현행 구성 백업 및 기준값 수집**  
   VLAN 목록, trunk 허용 목록, native VLAN, STP 모드/루트, LAG 구성, 단말 포트 매핑을 기록합니다.

2. **Juniper에 VLAN과 트렁크 설정을 사전 구성**  
   아직 서비스 경로로 사용하지 않는 상태에서 VLAN 존재 여부와 포트 설정을 검증합니다.

3. **중복 경로를 차단한 상태로 트렁크 한 구간만 연결**  
   한 번에 하나의 링크 또는 검증된 LAG만 활성화합니다. LAG를 사용할 경우 양쪽 모두 동일한 멤버 수와 논리 인터페이스 구성을 먼저 검증합니다.

4. **STP를 먼저 검증**  
   의도한 장비가 루트인지, 트렁크가 forwarding인지, BPDU가 정상인지 확인합니다.

5. **정상 VLAN과 문제 VLAN을 각각 시험**  
   동일 VLAN 내 단말 통신, 게이트웨이 통신, ARP 학습, MAC 학습, 양방향 ping을 확인합니다. 가능하면 패킷 캡처로 태그 유무도 확인합니다.

6. **액세스 포트를 소규모 단위로 이전**  
   한 번에 전체를 옮기지 말고 VLAN별·구간별로 이동한 뒤 각 단계마다 오류와 MAC flap을 확인합니다.

7. **구형 경로는 마지막에 제거**  
   모든 VLAN과 STP 상태가 안정된 후 기존 Cisco 경로를 차단하고, 일정 시간 동안 브로드캐스트량·MAC 이동·장애 로그를 관찰합니다.

핵심은 **문제 VLAN의 허용/태깅 확인과 동시에, 두 장비 사이의 실제 L2 중복 경로 및 STP 상호운용성을 먼저 통제하는 것**입니다. 루프가 진행 중이라면 VLAN 설정을 계속 변경하기보다, 우선 한 경로를 차단해 네트워크를 안정화한 뒤 비교 점검하는 것이 안전합니다.
