한 대만 시간이 어긋난다면 **NTP 서버보다 해당 스위치의 로컬 설정, NTP 동작 상태, 시간 저장 상태**를 먼저 확인하는 것이 맞습니다. 서버를 변경하는 것은 마지막 단계입니다.

## 1. 실제로 “시간”이 틀린 것인지 구분

먼저 다음을 비교합니다.

```text
show clock detail
show calendar
```

확인할 내용은 다음과 같습니다.

- 현재 표시 시간이 UTC인지 현지 시간인지
- `clock timezone` 설정이 다른 장비와 같은지
- `clock summer-time` 또는 서머타임 설정이 불필요하게 남아 있는지
- `show clock`과 하드웨어 시계인 `show calendar`가 서로 다른지
- 시간이 일정하게 몇 시간 차이 나는지, 계속 흐르면서 틀어지는지

정확히 몇 시간 단위로 차이가 나면 NTP 장애보다는 **타임존 또는 서머타임 설정 차이**일 가능성이 높습니다. 반대로 시간이 계속 빠르거나 느리면 NTP 미동기화 또는 하드웨어 시계 문제를 의심합니다.

## 2. NTP 동기화 상태 확인

```text
show ntp status
show ntp associations
```

확인할 항목은 다음과 같습니다.

- NTP가 synchronized 상태인지
- 선택된 서버가 있는지
- 서버 주소 왼쪽에 동기화 표시가 있는지
- stratum이 비정상적으로 높지 않은지
- reach 값이 계속 0이거나 서버가 unreachable인지
- 마지막 응답 시간과 offset이 과도하지 않은지

출력 형식과 필드명은 IOS/IOS XE 버전에 따라 다를 수 있으므로, 단순히 NTP 서버 주소가 설정되어 있다는 이유만으로 정상이라고 판단하면 안 됩니다.

## 3. 실행 설정과 시작 설정 비교

```text
show running-config | include ntp|clock timezone|clock summer-time
show startup-config | include ntp|clock timezone|clock summer-time
```

확인할 내용:

- NTP 서버 주소가 다른 장비와 같은지
- 잘못된 VRF 또는 소스 인터페이스 설정이 없는지
- `ntp source` 설정이 해당 장비에서 실제로 존재하는 인터페이스 주소인지
- 인증을 사용하는 경우 키, trusted key, 서버 설정이 모두 일치하는지
- 실행 설정에는 있지만 시작 설정에 저장되지 않은 변경 사항이 없는지
- 타임존과 서머타임 설정이 다른 장비와 동일한지

특히 유지보수나 재부팅 이후에만 문제가 발생했다면, 설정 미저장 또는 하드웨어 시계와 시스템 시계 간의 차이를 확인해야 합니다.

## 4. NTP 서버까지의 통신 경로 확인

NTP는 UDP 123을 사용합니다. 다음을 확인합니다.

- 해당 스위치의 라우팅 테이블에 NTP 서버 경로가 있는지
- 관리 VRF를 사용하는 경우 NTP도 올바른 VRF를 사용하는지
- 방화벽, ACL, CoPP에서 UDP/123을 차단하지 않는지
- `ntp source`로 지정한 인터페이스의 IP가 실제로 통신 가능한지
- NTP 서버가 이 스위치의 요청을 허용하는지

단순 ping이 성공해도 NTP가 정상이라는 뜻은 아닙니다. ICMP와 UDP/123은 별도로 허용될 수 있습니다. 다만 이 단계에서 서버 주소 자체가 도달 불가인지, 경로가 잘못되었는지는 확인할 수 있습니다.

## 5. 장비 자체의 상태 확인

다음 상황이 있었는지 확인합니다.

- 최근 재부팅 또는 전원 장애
- 부팅 직후부터 시간 오류 발생
- CPU 과부하 또는 프로세스 이상
- IOS/IOS XE 버그 가능성
- 하드웨어 시계 또는 배터리 문제
- 여러 NTP 서버 중 일부만 응답하는 상황

NTP가 현재 정상 동기화되고 있어도, `show calendar`가 크게 틀려 있으면 재부팅 시 다시 잘못된 시간으로 시작할 수 있습니다. 플랫폼과 IOS 버전에 따라 시스템 시계를 하드웨어 시계에 반영하는 방식이 다르므로, `ntp update-calendar` 지원 여부와 동작은 해당 장비의 명령어 가이드를 확인해야 합니다. 확실하지 않은 상태에서 임의로 시간 설정 명령을 실행하지 않는 것이 좋습니다.

## NTP 서버 변경 여부

**한 대만 틀리고 다른 장비가 같은 NTP 서버와 정상 동기화된다면, NTP 서버를 변경하는 것은 우선 접근이 아닙니다.**

다음 순서가 적절합니다.

1. 표시 시간과 타임존 차이 확인  
2. `show ntp status`, `show ntp associations`로 실제 동기화 여부 확인  
3. 실행/시작 설정 비교  
4. VRF, 소스 인터페이스, ACL, UDP/123 통신 확인  
5. 재부팅 이력과 하드웨어 시계 확인  
6. 필요하면 동일한 NTP 서버를 추가 서버로 구성하여 교차 검증

NTP 서버 변경은 여러 장비에서 동시에 동기화 실패가 발생하거나, 해당 서버의 응답·정확도·접근 정책에 문제가 확인된 경우에 검토하는 것이 맞습니다. 한 대만 문제라면 먼저 해당 스위치의 설정과 상태를 원인으로 보는 것이 합리적입니다.
