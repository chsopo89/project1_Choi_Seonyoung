FortiGate에서 로그가 생성되지 않거나 전송되지 않는 문제는 여러 요인에 의해 발생할 수 있습니다. 확인 점검 순서는 다음과 같습니다:

1. **로그 기능 활성화 확인**  
   - **확인 항목**: `System > Event Logs > Log Settings`에서 로그 기능이 **활성화**되었는지 확인합니다.  
   - **점검 순서**: 가장 먼저 로그 기능 자체가 비활성화된 경우를 확인해야 합니다. 예를 들어, 사용자가 실수로 `Log Settings`에서 기능을 꺼두면 로그가 생성되지 않습니다.

2. **로그 필터링 설정 점검**  
   - **확인 항목**: `Log Settings`에서 **로그 필터링 조건**이 특정 이벤트만 필터링하는 경우가 있는지 확인합니다.  
   - **점검 순서**: 예를 들어, 특정 심각도(예: "Emergency"만) 또는 특정 IP/정책에만 로그가 생성되도록 설정되어 있을 수 있습니다. 필터링 조건이 너무 좁아 특정 이벤트가 누락될 수 있습니다.

3. **디스크 공간 확인**  
   - **확인 항목**: `System > Disk Usage`에서 **내부 디스크 공간**이 부족한지 확인합니다.  
   - **점검 순서**: 로그 생성 시 내부 저장소가 가득 차면 로그가 저장되지 않거나 전송되지 않을 수 있습니다. `diagnose system disk usage` 명령어로 디스크 사용량을 확인해야 합니다.

4. **로그 전송 설정 검토**  
   - **확인 항목**: `System > Event Logs > Log Settings`에서 **로그 전송 설정**이 올바르게 구성되어 있는지 확인합니다.  
   - **점검 순서**: 로그 서버 IP, 포트, 프로토콜(Syslog, FTP 등)이 올바르게 설정되었는지 확인합니다. 예를 들어, Syslog의 경우 포트 514 UDP가 사용되므로 방화벽 규칙이 해당 포트를 차단하지 않는지 확인해야 합니다.

5. **로그 버퍼 상태 확인**  
   - **확인 항목**: `Log Settings`에서 **로그 버퍼 크기**가 제한되어 로그가 버퍼에 쌓일 수 있는지 확인합니다.  
   - **점검 순서**: 버퍼가 가득 차면 로그가 누적되지 않거나 전송되지 않을 수 있습니다. 버퍼 크기를 조정해야 할 수 있습니다.

6. **시스템 자원 점검**  
   - **확인 항목**: CPU, 메모리 사용량이 과도하게 높아 로그 처리가 지연되거나 중단되는지 확인합니다.  
   - **점검 순서**: `diagnose sys top` 명령어로 실시간 자원 사용량을 확인하여 과부하 상태가 있는지 점검합니다.

7. **로그 서버 연결 테스트**  
   - **확인 항목**: FortiGate에서 로그 서버로 전송하는 네트워크 연결이 정상인지 확인합니다.  
   - **점검 순서**: `diagnose test syslog <IP> <PORT>` 명령어로 로그 서버에 패킷이 전송되는지 테스트합니다. 이 명령어는 로그 전송을 위한 네트워크 경로가 차단되지 않았는지 확인합니다.

8. **시스템 로그 및 오류 확인**  
   - **확인 항목**: `System > Event Logs > System Logs`에서 **시스템 오류 메시지**가 있는지 확인합니다.  
   - **점검 순서**: 로그 생성/전송에 영향을 주는 시스템 오류(예: 네트워크 장애, 디스크 오류)가 있는지 확인합니다.

위 점검 순서를 따라가며, 확실하지 않은 명령어나 설정값은 추측하지 않고 점검해야 합니다. 예를 들어, `diagnose test syslog` 명령어는 로그 전송 테스트에 유용하지만, 실제 환경에 따라 결과가 다를 수 있습니다. 각 단계에서 확인된 문제가 없다면, 추가적인 네트워크 장비(예: 라우터/스위치)의 ACL이나 방화벽 규칙도 점검해야 합니다.
