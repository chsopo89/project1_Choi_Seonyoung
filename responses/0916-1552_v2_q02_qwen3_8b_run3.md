FortiGate의 Virtual IP(VIP)로 제공하는 웹 서비스가 중단된 경우, 문제의 원인과 점검 순서는 다음과 같습니다.  

1. **웹 서버 상태 점검**  
   - 웹 서버의 웹 서비스가 실행 중인지 확인합니다. (`systemctl status httpd` 또는 `nginx -t` 등 명령어 사용).  
   - 웹 서버에서 HTTP/HTTPS 포트(예: 80, 443)가 열려 있는지 확인합니다. (`netstat -tuln` 또는 `ss -tuln` 명령어로 포트 상태 확인).  
   - 웹 서버 로그(`/var/log/messages`, `/var/log/apache2/error.log` 등)에 오류 메시지가 있는지 확인합니다.  

2. **FortiGate VIP 및 정책 검토**  
   - VIP 설정이 정확한지 확인합니다. VIP가 웹 서버의 IP와 포트를 올바르게 매핑하고 있는지, 사용 중인 프로토콜(HTTP/HTTPS)이 올바른지 점검합니다.  
   - 정책에서 웹 트래픽을 허용하는 규칙이 있는지 확인합니다. 특히 **서비스 객체(Service Object)** 설정이 HTTP/HTTPS 프로토콜을 포함하고 있는지 확인합니다.  
   - **하이브리드 리드**(Hybrid Load Balancing)나 **건강 검사**(Health Check)가 활성화되어 있는 경우, 서버가 건강 상태를 유지하고 있는지 확인합니다.  

3. **방화벽 규칙 및 통신 경로 확인**  
   - FortiGate의 방화벽 규칙에서 HTTP/HTTPS 트래픽이 차단되는 명시적 차단 규칙(`explicit deny`)이 있는지 확인합니다.  
   - **NAT 설정**이 올바르게 구성되어 있는지 확인합니다. VIP가 NAT 트래픽을 처리하는 방식이 문제인지 점검합니다.  
   - **RPF(Routing Prefix Check)**나 **IPsec/SSLVPN 설정**이 웹 트래픽을 차단하지 않는지 확인합니다.  

4. **네트워크 테스트 및 트래픽 분석**  
   - 외부 클라이언트에서 VIP IP로 HTTP/HTTPS 요청을 직접 전송해 트래픽이 도달하는지 확인합니다.  
   - **tcpdump** 또는 **Wireshark**로 FortiGate와 웹 서버 간 네트워크 패킷을 캡처해 VIP가 트래픽을 전달하는지, 서버가 응답하는지 분석합니다.  
   - **Traceroute**나 **MTR**로 경로 문제를 확인합니다.  

5. **보안 장치 및 라우터 설정 확인**  
   - 다른 보안 장치나 라우터에서 웹 트래픽이 필터링되는지 확인합니다. 특히 **ACL(Access Control List)** 또는 **QoS** 설정이 웹 트래픽을 제한하는지 점검합니다.  

6. **시스템 로그 및 이벤트 점검**  
   - FortiGate의 시스템 로그(`diagnose sys log` 명령어)에서 VIP 관련 오류나 경고 메시지가 있는지 확인합니다.  
   - **DDoS 방어**나 **스팸 필터링** 기능이 웹 트래픽을 차단하지 않는지 확인합니다.  

7. **업데이트 및 호환성 확인**  
   - FortiGate의 **Firmware 버전**이 최신인지, 웹 서버의 서버 소프트웨어(예: Apache, Nginx)가 호환성 문제를 겪고 있는지 확인합니다.  
   - VIP 설정 및 웹 서버의 포트 구성이 **IPv4/IPv6** 프로토콜에 따라 올바르게 구성되어 있는지 확인합니다.  

**요약**: 문제는 **웹 서버의 서비스 상태**, **VIP의 프로토콜/포트 설정**, **방화벽의 규칙 또는 NAT 구성** 중 하나일 가능성이 높습니다. 우선순위는 웹 서버의 포트 상태 점검 → VIP 및 정책 검토 → 방화벽 규칙 분석 → 네트워크 트래픽 분석 순으로 진행해야 합니다. 확실하지 않은 설정은 추측 없이 문서나 구성 기록을 통해 확인해야 합니다.
