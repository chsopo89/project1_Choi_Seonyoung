NTP 설정이 정상이었지만 특정 스위치에서 시간 동기화가 실패한 경우, 다음과 같은 확인 절차를 통해 원인을 파악해야 합니다. **NTP 서버 변경은 우선적으로 추천되지 않으며**, 설정 검증과 네트워크 상태 점검을 먼저 수행해야 합니다.  

### 1. **NTP 설정 확인**  
   - **`show ntp configuration`** 명령어로 스위치의 NTP 설정을 확인합니다.  
     - NTP 서버 IP 주소가 올바르게 입력되었는지, IP 주소가 정확한지 점검합니다.  
     - `ntp server <IP>` 명령어가 구성되었는지 확인합니다.  
   - **`show ntp status`** 명령어로 NTP 동기화 상태를 확인합니다.  
     - **`clock is synchronized`** 문구가 표시되는지 확인합니다.  
     - **`reference-id`** 값이 NTP 서버 IP와 일치하는지 확인합니다.  

### 2. **NTP 서버 연결 상태 확인**  
   - **`show ntp peers`** 명령어로 NTP 서버와의 연결 상태를 확인합니다.  
     - **`reach`** 값이 16(255)인지 확인합니다. `reach` 값이 0이면 서버에 연결 실패입니다.  
     - **`poll-interval`** 값이 정상인지 확인합니다.  
   - **`ping`** 또는 **`tracert`** 명령어로 NTP 서버에 네트워크 연결이 가능한지 점검합니다.  

### 3. **NTP 인증 설정 검증**  
   - **`show ntp authentication`** 명령어로 인증 설정을 확인합니다.  
     - **`ntp authenticate`**가 활성화되어 있고, **`ntp trusted-key`** 설정이 있는 경우, 해당 키 값이 정확한지 확인합니다.  
     - 서버에서 인증이 실패할 경우 스위치가 서버 응답을 무시할 수 있습니다.  

### 4. **시간대 및 시계 설정 확인**  
   - **`show clock`** 명령어로 시계 설정을 확인합니다.  
     - 시간대가 올바르게 설정되었는지, `clock` 명령어로 수동 시간 설정이 이루어지지 않았는지 점검합니다.  
     - **`ntp update-calendar`** 명령어가 활성화되어 있는지 확인하여 하드웨어 시계와 소프트웨어 시계 동기화가 되는지 확인합니다.  

### 5. **NTP 서버 변경 여부**  
   - NTP 서버가 동일한 네트워크에서 다른 장치로 변경되는 경우, **서버의 동작 상태** 및 **네트워크 경로**를 확인해야 합니다.  
   - 기존 서버가 정상일 경우, **서버 변경은 우선적으로 피해야 합니다**.  
   - 변경이 필요한 경우, **새로운 서버의 정확성**과 **네트워크 연결 상태**를 먼저 검증해야 합니다.  

### 6. **로그 및 오류 메시지 확인**  
   - **`show logging`** 명령어로 NTP 관련 로그를 확인하여 에러 메시지나 경고를 점검합니다.  
   - 예: "NTP authentication failed", "No response from server" 등의 메시지가 있는지 확인합니다.  

### 7. **SWITCH의 하드웨어 시계 상태**  
   - **`show clock`** 명령어로 하드웨어 시계의 정확성을 점검합니다.  
   - NTP 동기화가 실패할 경우, 하드웨어 시계가 오래된 시간을 유지할 수 있습니다.  

### **결론**  
NTP 서버 자체가 정상인 경우, 문제는 스위치의 설정, 네트워크 연결, 또는 인증 설정에 있습니다. **NTP 서버 변경은 원인 파악 전에 추천되지 않으며**, 위 점검 항목을 순차적으로 수행해야 합니다. 변경이 필요할 경우, 서버의 정확성과 네트워크 상태를 꼭 확인해야 합니다.
