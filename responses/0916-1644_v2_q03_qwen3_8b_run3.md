FortiGate에서 로그가 쌓이지 않고 로그 서버로 전송되지 않는 문제를 해결하기 위해서는, 로그 생성 및 전송 관련 구성, 네트워크 연결, 상태 확인 등을 점검해야 합니다. 아래는 점검 순서와 확인할 항목입니다:

1. **로그 설정 및 저장 방식 확인**  
   - FortiGate에서 로그가 로컬에 저장되는지 확인하세요. `diagnose log database list` 명령어를 통해 로컬 로그 DB의 상태를 확인할 수 있습니다.  
   - 로그가 로컬에 저장되지 않는다면, 로그 저장 설정(`config log memory`)이 정확히 구성되어 있는지 확인하세요.  
   - 로그 저장 용량 제한이 도달했는지 확인합니다. `diagnose log memory` 명령어를 통해 현재 사용량을 확인하세요.

2. **로그 서버 설정 및 상태 확인**  
   - 로그 서버 설정(`config log forward`)이 정확히 구성되어 있는지 확인하세요.  
   - 로그 서버 IP, 포트, 프로토콜(예: TCP, UDP, Syslog)이 올바르게 설정되어 있는지 점검합니다.  
   - 로그 서버의 로그 수신 설정 및 포트 방화벽 규칙이 문제인지 확인합니다. 이는 다른 장비에서 확인해야 할 점입니다.

3. **로그 전송 경로 확인**  
   - FortiGate의 네트워크 인터페이스 설정(`config system interface`)에서 로그 전송 경로와 관련된 인터페이스가 올바르게 설정되어 있는지 확인하세요.  
   - 방화벽 규칙(`config firewall policy`)에서 로그 전송이 허용되는지 확인하세요.

4. **로그 전송 상태 확인**  
   - `diagnose log forward list` 명령어를 통해 로그 전송 상태를 확인하세요. 이 명령어는 전송 중인 로그 및 전송 실패 상태를 보여줍니다.  
   - 전송 실패 시, `diagnose log forward status` 명령어로 전송 상태를 확인하고, 실패 원인을 분석합니다.

5. **시스템 및 네트워크 상태 점검**  
   - FortiGate의 CPU 및 메모리 사용률이 과도한지 확인하세요. `diagnose sys top` 명령어로 확인합니다.  
   - 네트워크 인터페이스 상태를 점검하세요. `diagnose sys interface` 명령어로 인터페이스의 상태와 통신 상태를 확인합니다.

6. **로그 서버에서 수신 로그 확인**  
   - 로그 서버에서 실제로 로그를 수신하고 있는지 확인합니다. 시스템 로그, 네트워크 포트 상태, 로그 관리 도구 등을 통해 확인해야 합니다. 이는 다른 장비에서 확인해야 할 점입니다.

7. **고급 설정 및 디버깅 옵션 활용**  
   - 로그 전송 디버깅 옵션(`set log forward debug`)을 활성화하여 상세한 디버그 정보를 확인합니다.  
   - `diagnose log test` 명령어로 로그 전송을 테스트합니다.

점검 시, 명확하지 않은 설정이나 명령어는 추측하지 않고, 정확한 설정을 확인해야 합니다. 위 순서에 따라 점검하면 원인을 파악할 수 있습니다.
