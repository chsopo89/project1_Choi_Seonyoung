IPsec VPN 연결이 터널 구간 통신은 되지만, 전체 연결 상태가 **disable**로 표시되는 문제는 일반적으로 다음과 같은 요소들이 원인일 수 있습니다. 확인할 항목과 점검 순서는 다음과 같습니다.

### 1. **IPsec 터널 연결 상태 확인 (터널별 상태)**
- 터널 단위로는 통신이 정상이므로, 터널 자체는 정상입니다.
- 하지만 전체 VPN 연결 상태가 **disable**로 표시되는 경우는, 해당 터널이 **사용 중**이지 않거나, **정책에 의해 자동으로 종료되었을 수 있습니다**.
- 따라서, **정책 또는 라우트 설정이 문제가 될 수 있습니다**.

### 2. **정책 설정 확인 (FortiGate / NetScreen)**
- **FortiGate**에서는 'Policy' 또는 'Security Policy'에서 해당 IPsec 터널을 사용하는 **정책이 활성화되어 있는지 확인**해야 합니다.
- **NetScreen**은 'VPN Policy'에서 해당 터널이 활성화되었는지 확인해야 합니다.
- 만약 해당 정책이 비활성화된 상태라면, 터널이 사용되지 않아 전체 상태가 **disable**로 표시될 수 있습니다.

### 3. **IPsec 터널 상태 확인 (터널별 상태)**
- **FortiGate**의 `diagnose vpn ike sa list` 또는 `diagnose vpn ipsec sa list` 명령어로, IKE 및 IPsec 세션이 생성되었는지 확인합니다.
- **NetScreen**에서는 `show vpn ipsec sa` 또는 `show vpn ike sa` 명령어로 상태를 확인합니다.

### 4. **IPsec 정책 설정 확인 (FortiGate / NetScreen)**
- 정책의 **정책 ID**, **IKE 프로세스**, **IPsec 정책**, **트래픽 필터링 조건** 등을 비교합니다.
- **트래픽이 해당 정책에 포함되지 않으면** 터널이 활성화되지 않을 수 있습니다.
- **IPsec 정책에 적용된 라우트가 잘못 설정되면** 트래픽이 터널을 지나지 못할 수 있습니다.

### 5. **라우트 설정 확인 (FortiGate / NetScreen)**
- **FortiGate**에서는 `diagnose router static` 명령어로 라우트 테이블을 확인합니다.
- **NetScreen**에서는 `show route` 명령어로 라우트가 올바르게 설정되었는지 확인합니다.
- **터널에 할당된 라우트가 없거나, 잘못 설정된 경우**, 트래픽이 터널을 통해 전달되지 않을 수 있습니다.

### 6. **인터페이스 설정 및 IP 주소 확인**
- **터널이 생성될 수 있는 인터페이스가 활성화되었는지**, **IP 주소가 올바르게 설정되었는지 확인**합니다.
- 예를 들어, **FortiGate**에서 `diagnose sys int list` 명령어로 인터페이스 상태를 확인할 수 있습니다.

### 점검 순서 요약
1. **정책 활성화 상태 확인**
2. **IPsec 터널 상태 확인**
3. **IPsec 정책 설정 비교**
4. **라우트 설정 확인**
5. **인터페이스 및 IP 주소 확인**

### 결론
**정책 활성화 여부**가 먼저 확인되어야 하며, **FortiGate**와 **NetScreen**의 정책 설정을 서로 비교하고 확인해야 합니다. **정책이 비활성화 상태라면**, 터널이 사용되지 않아 전체 연결 상태가 **disable**로 표시될 수 있습니다. 따라서 **정책 설정이 먼저 점검**되어야 하며, **정책이 활성화되어 있지 않다면** 해당 설정을 수정해야 합니다. 확실하지 않은 명령어나 설정값에 대해서는 추측하지 않고, 정확한 명령어나 설정값을 확인해야 합니다.
