## Cisco 스위치에서 Juniper 스위치로 전환 시 문제 해결 및 점검 순서

현재 상황은 Cisco 스위치에서 Juniper 스위치로 전환 중이며, 802.1Q 트렁크 및 VLAN ID 일치, LLDP 인식은 정상적으로 이루어지고 있지만 일부 VLAN 통신 문제 및 간헐적인 루프 트래픽 발생으로 인해 어려움을 겪고 계시는군요. 특히 각 스위치 내부에서는 단말 간 통신이 정상적으로 이루어지고 있다는 점이 중요합니다.

이 문제를 해결하기 위해서는 체계적인 점검과 단계별 접근이 필요합니다. 아래는 문제 해결을 위한 확인 항목 및 점검 순서, 그리고 이전 작업 진행 시 안전을 위한 제안입니다.

**1단계: 문제 심각도 평가 및 정보 수집 (1시간)**

* **문제 재현 및 기록:** 간헐적인 루프 트래픽 및 문제 발생 VLAN을 정확하게 기록합니다. 시간대별, 특정 활동과의 연관성 등을 파악합니다.
* **현재 네트워크 구성 확인:** 두 스위치의 구성 (VLAN, 인터페이스 설정, 라우팅 설정, QoS 설정 등)을 비교하고 차이점을 상세하게 기록합니다. 특히 802.1Q 트렁크 설정이 정확하게 동일하게 구성되었는지 확인합니다.
* **오류 로그 확인:** 두 스위치의 시스템 로그 및 오류 로그를 확인합니다. 루프 트래픽 관련 메시지, 패킷 손실 관련 메시지, 인터페이스 에러 메시지 등을 꼼꼼하게 분석합니다.
* **단말 측 확인:** 문제 VLAN에 접속된 단말에서 ping, traceroute 등을 통해 네트워크 연결 상태를 확인합니다. 해당 단말에서 발생하는 트래픽 분석을 통해 문제의 근본적인 원인을 파악할 수 있습니다.

**2단계: 802.1Q 트렁크 설정 점검 (2시간)**

* **트렁크 포트 설정 확인:** 두 스위치의 트렁크 포트 설정 (CRC 활성화/비활성화, 프레임 크기, 폴링 주기)이 동일하게 설정되었는지 확인합니다.
* **MTU 설정 확인:** 두 스위치의 트렁크 포트 MTU 설정이 동일하게 설정되었는지 확인합니다. MTU 불일치는 패킷 손실 및 루프 트래픽 발생의 원인이 될 수 있습니다.
* **802.1Q VLAN ID 설정 확인:** VLAN ID가 두 스위치에서 동일하게 설정되었는지, 그리고 해당 VLAN ID가 올바르게 구성되었는지 확인합니다.
* **트렁크 셀 설정 확인:** 802.1Q 트렁크 셀 설정 (VLAN ID, 프로토콜)이 정확하게 설정되었는지 확인합니다.
* **802.1Q 성능 설정 확인:** 802.1Q 성능 설정 (큐 크기, 우선순위 설정)이 네트워크 상황에 맞게 설정되었는지 확인합니다. (기본 설정은 문제 발생에 영향을 미칠 수 있습니다.)

**3단계: 인터페이스 및 루프 방지 설정 점검 (3시간)**

* **포트 상태 확인:** 각 인터페이스의 상태 (Up/Down), 오류 횟수, 패킷 손실 횟수 등을 확인합니다.
* **루프 방지 기능 확인:**  두 스위치 모두 루프 방지 기능 (Spanning Tree Protocol - STP, Rapid Spanning Tree Protocol - RSTP, Link Aggregation Control Protocol - LACP)이 올바르게 구성되었는지 확인합니다.
* **STP/RSTP 설정 확인:**  STP/RSTP의 설정 (Root Bridge, Port Cost, Priority)이 네트워크 토폴로지에 맞게 설정되었는지 확인합니다. 특히 Root Bridge가 올바르게 선택되었는지 확인하는 것이 중요합니다.
* **LACP 설정 확인:** LACP가 활성화되어 있다면, LACP 설정 (Aggregator ID, 활성화/비활성화)이 두 스위치에서 동일하게 설정되었는지 확인합니다.
* **포트 모드 확인:** 트렁크 포트가 트렁크 모드로 설정되어 있는지 확인합니다.

**4단계: 고급 설정 점검 및 분석 (4시간)**

* **MAC 주소 테이블 확인:** 두 스위치의 MAC 주소 테이블이 서로 통신하는 장비의 MAC 주소를 학습하고 있는지 확인합니다. 학습되지 않았다면 MAC Learning 프로토콜 (BPDU) 설정이 제대로 이루어졌는지 확인합니다.
* **패킷 캡처:** Wireshark 등의 패킷 캡처 도구를 사용하여 두 스위치 간의 트래픽을 캡처하고 분석합니다. 패킷 손실, VLAN ID 불일치, 프레임 손상 등을 확인합니다.
* **QoS 설정 확인:** QoS 설정이 특정 VLAN에 우선순위를 부여하고 있는지 확인합니다. QoS 설정 불일치는 성능 저하나 통신 문제 발생의 원인이 될 수 있습니다.
* **ARP 테이블 확인:** ARP 테이블에 등록된 IP 주소와 MAC 주소의 일치 여부를 확인합니다. ARP 테이블 불일치는 IP 주소 충돌을 유발할 수 있습니다.

**이전 작업 진행 시 안전한 순서**

1. **준비 단계:**
   * 이전 Cisco 스위치에 대한 상세 네트워크 구성 정보 (VLAN, 인터페이스, 라우팅 등)를 문서화합니다.
   * Juniper 스위치에 동일한 네트워크 구성 (VLAN, 인터페이스, 라우팅 등)을 적용합니다.
   * LLDP 기능 활성화 및 작동 확인 (서로 스위치 인식 확인)
2. **트렁크 설정:** 802.1Q 트렁크 설정 및 VLAN ID 일치 확인
3. **기본 기능 활성화:** STP/RSTP, LACP (필요한 경우) 활성화 및 작동 확인
4. **단말 연결 테스트:** VLAN별로 단말 연결 테스트 진행
5. **최종 점검 및 설정 조정:** 문제 발생 VLAN에 대한 추가 점검 및 설정 조정
6. **모니터링 설정:** 네트워크 모니터링 시스템을 통해 실시간으로 네트워크 상태를 모니터링

**주의사항:**

* **변경 관리:** 네트워크 변경 사항은 변경 관리 시스템을 통해 기록하고 승인해야 합니다.
* **백업:** 변경 전에 기존 네트워크 설정을 백업해두는 것이 좋습니다.
* **점진적인 변경:**  한 번에 모든 설정을 변경하는 대신, 점진적으로 변경하고 테스트하는 것이 안전합니다.
* **문서화:** 모든 변경 사항을 상세하게 문서화합니다.

**추가적으로 필요한 정보:**

*   **Cisco 스위치 모델명 및 Juniper 스위치 모델명:** 스위치 모델에 따라 설정 방법이 다를 수 있습니다.
*   **사용 중인 VLAN 정보:** 각 VLAN에 할당된 IP 주소, 서브넷 마스크, 라우팅 정보 등을 확인해야 합니다.
*   **네트워크 토폴로지:** 두 스위치가 네트워크에서 어떤 위치에 있는지, 어떤 장비와 연결되어 있는지 확인해야 합니다.
*   **최신 Juniper 스위치 설정 매뉴얼:** Juniper 스위치 모델에 맞는 최신 설정 매뉴얼을 참고하여 설정을 진행해야 합니다.

위의 점검 항목 및 진행 순서를 통해 문제를 해결하고, Cisco 스위치에서 Juniper 스위치로의 전환을 안전하게 완료할 수 있기를 바랍니다. 추가적인 질문이 있으시면 언제든지 문의해주세요.
