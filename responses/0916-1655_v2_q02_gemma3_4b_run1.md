## FortiGate Virtual IP (VIP) 웹 서비스 중단 문제 해결 가이드

웹 서비스 중단 문제에 대한 초기 진단 및 점검 순서를 안내합니다. 제공된 정보만으로는 정확한 원인 파악이 어려우므로, 아래 단계를 체계적으로 진행하며 추가 정보를 수집해야 합니다.

**1. 상황 파악 및 초기 진단 (300분)**

* **문제 재현 여부 확인:** 다른 네트워크 환경에서도 동일한 문제가 발생하는지 확인합니다. (예: 다른 FortiGate 장비, 다른 네트워크 세그먼트)
* **증상 상세 파악:**
    * 중단 시점: 정확히 언제부터 문제가 발생했는지 (시간, 날짜) 확인합니다.
    * 문제 발생 패턴: 특정 시간대에만 발생하는지, 아니면 무작위로 발생하는지 확인합니다.
    * 오류 메시지: FortiGate 로그, 웹서버 로그, 네트워크 장비 로그에 오류 메시지가 있는지 확인합니다. 특히 FortiGate의 `System Log`, `Web Filter Log`, `Application Firewall Log`를 집중적으로 검토합니다.
    * 사용자 영향: 영향을 받는 사용자가 누구인지, 어떤 기능이 동작하지 않는지 파악합니다.
* **기본 설정 재확인:**
    * VIP 설정: VIP 주소, 서브넷 마스크, 게이트웨이 주소, 대상 (웹 서버 IP 주소)이 올바르게 설정되었는지 확인합니다.
    * 정책 설정: VIP를 대상으로 하는 방화벽 정책이 정상적으로 구성되었는지 (방향, 프로토콜, 포트, 서비스) 확인합니다.
    * 웹서버 상태: 웹 서버의 CPU, 메모리, 디스크 사용량, 프로세스 상태 등을 확인하여 서버 자체의 문제가 없는지 확인합니다. (SSH 접속 시 상태 확인)

**2. FortiGate 설정 및 로그 점검 (1000자)**

가장 먼저 FortiGate에서 다음과 같은 부분을 집중적으로 점검해야 합니다.

* **VIP 관련 설정:**
    * VIP 설정 값(IP, Subnet, Gateway)이 정확한지 다시 한번 확인합니다. 설정 오류는 가장 흔한 원인 중 하나입니다.
    * VIP는 FortiGate의 어떤 인터페이스를 통해 연결되어 있는지 확인합니다. (예: 라인 인터페이스, 루프백 인터페이스)
* **정책 설정:** VIP를 대상으로 하는 정책의 모든 설정 (방향, 프로토콜, 포트, 서비스, 고급 설정)을 면밀히 검토합니다. 특히, 정책의 우선순위가 높은 정책이 VIP 트래픽을 차단하고 있는지 확인합니다.
* **로그 분석:** 다음 로그들을 확인하여 문제 해결의 단서를 찾습니다.
    * **System Log:** FortiGate 시스템 관련 오류, 경고, 정보 메시지를 확인합니다.  (예: 시스템 오류, 메모리 부족, 프로세스 오류)
    * **Web Filter Log:** 웹 방화벽 관련 로그를 확인합니다.  (예:  방화벽 정책 적용 거부,  웹 서비스 차단,  URL 필터링 오류)
    * **Application Firewall Log:**  애플리케이션 방화벽 관련 로그를 확인합니다. (예: 특정 애플리케이션 트래픽 차단,  애플리케이션별 정책 오류)
    * **Traffic Log:**  VIP를 통해 발생하는 모든 트래픽 로그를 확인합니다. (방향, 포트, 프로토콜, 시간 등)  특정 시간대에 발생하는 트래픽의 패턴을 분석하여 문제의 원인을 추정할 수 있습니다.
* **QoS 설정:** Quality of Service (QoS) 설정이 VIP 트래픽에 영향을 미치지 않는지 확인합니다.  QoS 설정이 VIP 트래픽을 제한하거나 우선순위를 낮출 수 있습니다.
* **Firmware 버전:** FortiGate의 firmware 버전이 최신 버전인지 확인합니다.  오래된 firmware 버전은 버그를 포함할 수 있습니다.

**3. 네트워크 트래픽 분석 (500자)**

FortiGate 설정 외에도 네트워크 트래픽 분석을 통해 문제 해결에 도움이 될 수 있습니다.

* **패킷 캡처 (PCAP):**  FortiGate의 라인 인터페이스 또는 웹서버의 네트워크 인터페이스에서 PCAP를 캡처하여 트래픽 흐름을 분석합니다.  특히, VIP에서 발생하는 트래픽과 웹서버로 향하는 트래픽을 집중적으로 분석합니다.
* **Wireshark 활용:**  캡처된 패킷을 Wireshark와 같은 네트워크 분석 도구로 분석하여 문제의 원인을 파악합니다. (예:  TCP 핸드셰이크 오류,  HTTP 응답 코드 오류,  데이터 손실)
* **traceroute:**  트래커트를 실행하여 FortiGate와 웹서버 간의 네트워크 경로를 확인하고, 경로 상의 병목 지점이나 오류가 있는지 확인합니다.

**4. 추가 확인 사항 (500자)**

* **DNS 설정:** 웹서버의 도메인 이름이 DNS 서버에서 올바르게 해석되고 있는지 확인합니다.
* **MTU (Maximum Transmission Unit) 설정:** FortiGate와 웹서버 간의 MTU 설정이 호환되는지 확인합니다.  MTU 설정 불일치는 패킷 손실 및 연결 문제를 일으킬 수 있습니다.
* **라우팅 테이블:** FortiGate의 라우팅 테이블이 웹서버로 향하는 경로를 올바르게 설정하고 있는지 확인합니다.
* **타임아웃 설정:** 웹서버의 타임아웃 설정이 VIP에서 발생하는 트래픽을 제대로 처리할 수 있는지 확인합니다.  타임아웃 설정이 너무 짧으면 웹서버가 연결을 끊을 수 있습니다.
* **FortiGate 재시작:** FortiGate 장비를 재시작하여 일시적인 문제를 해결해 봅니다. (장비 재시작 전, 설정 변경 사항을 반드시 백업해야 합니다.)

**주의 사항:**

*   명확한 오류 메시지나 로그가 없는 경우, 문제 해결이 어려울 수 있습니다.
*   FortiGate 설정 변경 시, 변경 사항을 적용하기 전에 반드시 백업해야 합니다.
*   문제 해결 과정에서 발생하는 모든 변경 사항을 기록하고, 문제 해결 후에는 변경 사항을 되돌릴 수 있도록 준비해야 합니다.

**추가 정보 요청:**

위의 점검 사항을 진행하면서 다음과 같은 추가 정보를 요청해야 합니다.

*   FortiGate 모델명 및 firmware 버전
*   웹서버 OS 및 버전
*   웹 서비스의 종류 (예:  HTTP, HTTPS, FTP)
*   웹 서비스에 사용되는 프로토콜 (예:  TCP, UDP)
*   웹 서비스의 아키텍처 (예:  단일 서버, 로드 밸런서)

위의 단계를 체계적으로 진행하고, 추가 정보를 수집하여 문제의 원인을 정확하게 파악하고 해결할 수 있을 것입니다.
