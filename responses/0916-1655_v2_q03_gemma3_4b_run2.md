네트워크 엔지니어로서 FortiGate에서 로그가 쌓이지 않고 로그 서버로 전송되지 않는 문제에 대해 진단하고 해결 방법을 제시하겠습니다. 주어진 정보(로그 서버 정상 동작, 설정 및 정책 확인, ping 정상)를 바탕으로 문제 해결을 위한 체계적인 점검 순서를 제안합니다. 

**1. 문제 정의 및 초기 상황 파악**

*   **증상 재확인:** 로그가 쌓이지 않고 로그 서버로 전송되지 않는다는 점을 명확히 확인합니다. 로그 서버의 상태를 다시 한번 확인하고, FortiGate 자체의 로그 기록 여부도 확인합니다.
*   **문제 발생 시점:** 문제 발생 시점을 정확히 파악합니다. 특정 시간대에 문제가 발생했는지, 아니면 지속적으로 발생하는지 확인합니다.
*   **변동 사항:** 최근 FortiGate 설정 변경 사항이 있는지 확인합니다. 새로운 정책, 기능, 또는 시스템 업데이트가 적용된 적이 있다면 문제 발생 시점과 관련이 있을 수 있습니다.
*   **로그 서버 정보:** 로그 서버의 모델, 운영체제, FortiGate와 연결된 방식(예: SCP, SFTP, HTTP), 그리고 FortiGate의 로그 전송 설정 정보를 확인합니다.

**2. FortiGate 로그 설정 점검**

가장 먼저 FortiGate 자체의 로그 설정이 제대로 구성되었는지 확인합니다. 

*   **로그 활성화:** FortiGate의 로그 기능이 활성화되어 있는지 확인합니다. 설정 -> System -> Logging에서 로그 설정을 확인하고, 로그 기록 활성화 여부를 확인합니다.
*   **로그 유형:** 어떤 종류의 로그를 기록하도록 설정되었는지 확인합니다. (예: Firewall, IPS, Application, System 등) 문제의 원인이 특정 로그 유형에 있을 수 있습니다.
*   **로그 저장 위치:** 로그가 저장될 위치(FortiGate 자체 또는 로그 서버)가 올바르게 설정되어 있는지 확인합니다.
*   **로그 볼륨 설정:** 로그 볼륨 설정이 너무 낮게 설정되어 로그가 압도되어 기록되지 않을 수 있습니다. 로그 볼륨 설정을 점진적으로 늘려가면서 문제가 해결되는지 확인합니다.
*   **로그 필터링:** 특정 이벤트만 기록하도록 필터링 설정이 되어 있는지 확인합니다. 필터링 설정이 너무 엄격하면 로그가 기록되지 않을 수 있습니다.
*   **로그 저장 공간:** FortiGate의 로그 저장 공간이 가득 찼는지 확인합니다. 저장 공간이 부족하면 로그 기록이 중단될 수 있습니다.
*   **로그 기록 모드:** 로그 기록 모드가 "Overwrite" 모드로 설정되어 있는지 확인합니다. "Append" 모드에서는 이전 로그가 삭제되지 않으므로 로그가 쌓이지 않습니다.

**3. 로그 전송 설정 점검**

FortiGate에서 로그 서버로의 전송 설정이 제대로 구성되었는지 확인합니다.

*   **전송 방식:** 로그 전송 방식(SCP, SFTP, HTTP 등)이 FortiGate와 로그 서버 간의 연결 방식과 일치하는지 확인합니다.
*   **서버 주소:** 로그 서버의 IP 주소 또는 호스트 이름이 FortiGate 설정과 정확히 일치하는지 확인합니다.
*   **포트:** 로그 전송에 사용되는 포트(예: 22 for SSH, 80 for HTTP)가 방화벽 규칙에 의해 허용되는지 확인합니다.
*   **사용자 이름/암호:** 로그 전송에 사용되는 사용자 이름과 암호가 FortiGate 설정과 정확히 일치하는지 확인합니다.
*   **SSL/TLS 설정:** SSL/TLS를 사용하여 로그 전송을 수행하는 경우, SSL/TLS 설정이 FortiGate와 로그 서버 간의 연결에 적합한지 확인합니다.
*   **전송 주기:** 로그 전송 주기가 너무 길게 설정되어 실시간 로그 전송이 제대로 이루어지지 않을 수 있습니다. 전송 주기를 점검하고 필요에 따라 조정합니다.
*   **전송 오류:** 로그 전송 과정에서 오류가 발생하는지 확인합니다. FortiGate의 로그 설정을 통해 전송 오류 메시지를 확인하고, 로그 서버의 로그 파일에서 FortiGate의 전송 관련 로그를 확인합니다.

**4. 네트워크 연결 점검**

FortiGate와 로그 서버 간의 네트워크 연결에 문제가 있는지 확인합니다.

*   **ping 테스트:** ping 테스트가 정상적으로 작동하는지 다시 한번 확인합니다.
*   **traceroute:** traceroute 명령어를 사용하여 FortiGate와 로그 서버 간의 네트워크 경로를 확인하고, 경로 상에 문제가 있는지 확인합니다.
*   **방화벽 규칙:** FortiGate의 방화벽 규칙이 FortiGate와 로그 서버 간의 통신을 차단하고 있는지 확인합니다.
*   **DNS 설정:** FortiGate의 DNS 설정이 로그 서버의 호스트 이름을 정확하게 해석하는지 확인합니다.
*   **MTU 설정:** FortiGate와 로그 서버의 MTU 설정이 호환되는지 확인합니다. MTU 설정 불일치는 데이터 패킷 분할 및 재조립 문제를 일으켜 로그 전송에 영향을 줄 수 있습니다.

**5. 로그 서버 점검**

로그 서버 자체의 문제 가능성을 배제하지 않고 점검합니다.

*   **로그 서버 로그:** 로그 서버의 로그 파일을 확인하여 FortiGate로부터 로그 전송 관련 오류 메시지가 있는지 확인합니다.
*   **로그 서버 용량:** 로그 서버의 디스크 용량이 충분한지 확인합니다.
*   **로그 서버 서비스:** 로그 서버에서 로그 수신 서비스를 정상적으로 실행 중인지 확인합니다.

**6. 문제 해결을 위한 추가 단계**

*   **로그 덤프:** FortiGate의 로그를 덤프하여 로그 서버로 전송되는 데이터의 내용을 확인합니다. 이 정보를 통해 로그 전송 과정의 문제점을 파악할 수 있습니다.
*   **FortiGate 재부팅:** FortiGate를 재부팅하여 일시적인 오류를 해결합니다.
*   **FortiGate 업데이트:** FortiGate 펌웨어를 최신 버전으로 업데이트합니다.
