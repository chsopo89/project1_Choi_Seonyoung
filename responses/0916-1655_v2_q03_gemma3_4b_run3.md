네트워크 엔지니어로서 FortiGate에서 로그가 쌓이지 않고 로그 서버로 전송되지 않는 문제에 대한 점검을 진행하겠습니다. 주어진 정보(로그 서버 정상 작동, 설정 및 정책 확인, ping 정상)를 바탕으로 가능한 원인을 추정하고, 효율적인 점검 순서를 제시하겠습니다.

**1. 문제 정의 및 추가 정보 확보**

*   **정확한 증상:** 로그가 쌓이지 않는다는 것은 FortiGate의 시스템 로그, 이벤트 로그, 보안 로그 등 모든 로그가 비어있는 상태를 의미하는지 확인합니다. 로그가 단순히 빈 상태인지, 아니면 로그 항목이 생성되는 것을 보지 못하고 단순히 저장되지 않는지만 보이는지 파악해야 합니다.
*   **로그 서버 정보:** 로그 서버의 종류, 운영체제, FortiGate와 로그 서버 간의 연결 방식 (예: Syslog, FTPS, HTTP)을 명확히 파악합니다. 또한, 로그 서버에 접속하여 FortiGate에서 전송된 로그 데이터가 실제로 존재하는지 확인합니다.
*   **FortiGate 모델 및 버전:** FortiGate의 정확한 모델명과 소프트웨어 버전을 확인합니다. 모델별로 버전에 따른 로그 설정 및 동작 방식이 다를 수 있습니다.
*   **로그 전송 설정:** FortiGate의 로그 전송 설정(대상 서버, 로그 유형, 전송 주기 등)을 꼼꼼히 확인합니다. 특히, 설정 오류로 인해 로그가 전송되지 않을 가능성을 배제하지 않습니다.
*   **네트워크 환경:** FortiGate와 로그 서버 간의 네트워크 경로(라우터, 방화벽 등)에 문제가 없는지 확인합니다.

**2. 점검 순서 및 내용**

다음은 문제 해결을 위한 점검 순서입니다. 각 단계별로 상세하게 점검하고, 결과를 기록하여 문제 해결에 도움이 되도록 합니다.

**2.1. 기본 설정 확인 (1시간)**

1.  **FortiGate 재부팅:** 간단한 문제 해결을 위해 FortiGate를 재부팅합니다.
2.  **로그 설정 확인:**
    *   **로그 저장 정책:** 로그 저장 정책이 활성화되어 있는지, 저장 용량이 충분한지 확인합니다. 저장 정책이 비활성화되어 있으면 로그가 저장되지 않습니다.
    *   **로그 전송 설정 확인:** 로그 전송 설정(대상 서버, 로그 유형, 전송 주기 등)이 정확하게 구성되어 있는지 확인합니다. 특히, 잘못된 IP 주소 또는 포트 설정은 로그 전송 실패의 주요 원인입니다.
    *   **로그 수집 설정 확인:** FortiGate에서 로그를 수집하는 설정(예: Syslog 수집 설정)이 활성화되어 있는지 확인합니다.
3.  **시스템 로그 확인:** FortiGate의 시스템 로그에서 오류 메시지나 경고를 확인합니다. 시스템 로그는 장비의 일반적인 동작 상태에 대한 정보를 제공합니다.

**2.2. 로그 전송 설정 점검 (2시간)**

1.  **로그 전송 방식 확인:** FortiGate에서 로그를 전송하는 방식 (Syslog, FTPS, HTTP 등)을 확인합니다. 각 방식별로 설정 방법이 다르므로, 설정 오류 가능성을 점검합니다.
2.  **Syslog 설정 점검 (Syslog 사용 시):**
    *   **Syslog 서버 설정:** Syslog 서버의 IP 주소, 포트, 인증 설정(필요한 경우)이 정확하게 구성되어 있는지 확인합니다.
    *   **Syslog 수집 설정:** FortiGate의 Syslog 수집 설정(수집 주기, 메시지 필터 등)이 올바르게 설정되어 있는지 확인합니다.
    *   **Syslog 필터 확인:** 특정 로그 유형을 필터링하는 설정이 로그 전송을 방해하지 않는지 확인합니다.
3.  **FTPS/HTTP 설정 점검 (FTPS/HTTP 사용 시):**
    *   **서버 인증 설정:** FTPS 서버의 인증 설정(사용자 이름, 비밀번호, 인증 방식)이 정확하게 구성되어 있는지 확인합니다.
    *   **포트 설정:** FTPS/HTTP 서버의 포트 설정이 FortiGate에서 접근 가능한지 확인합니다.
    *   **SSL/TLS 설정:** FTPS를 사용하는 경우, SSL/TLS 설정이 올바르게 구성되어 있는지 확인합니다.

**2.3. 네트워크 점검 (1시간)**

1.  **Ping 정상 확인:** 이미 ping이 정상 작동한다는 정보가 주어졌지만, 다시 한번 ping 테스트를 수행하여 네트워크 연결 상태를 확인합니다.
2.  **방화벽 규칙 확인:** FortiGate의 방화벽 규칙이 로그 서버로 향하는 트래픽을 차단하지 않는지 확인합니다.
3.  **라우팅 테이블 확인:** FortiGate의 라우팅 테이블이 로그 서버로의 경로를 올바르게 설정하고 있는지 확인합니다.
4.  **방화재 설정 확인:** 네트워크 장비(라우터, 방화벽 등)의 방화재 설정이 FortiGate와 로그 서버 간의 통신을 차단하지 않는지 확인합니다.

**2.4. 고급 점검 (필요 시) (2시간 이상)**

1.  **FortiGate 이벤트 로그 확인:** 이벤트 로그는 시스템 이벤트 및 보안 이벤트에 대한 정보를 제공합니다. 이벤트 로그에서 오류 메시지나 경고를 확인하여 문제의 원인을 파악합니다.
2.  **로그 서버 로그 확인:** 로그 서버의 로그 파일에서 FortiGate에서 전송된 로그 데이터가 실제로 존재하는지 확인합니다. 로그 서버 로그는 FortiGate와 로그 서버 간의 통신 상태를 파악하는 데 도움이 됩니다.
3.  **FortiGate 시스템 헬스 체크 확인:** FortiGate의 시스템 헬스 체크가 정상적으로 작동하는지 확인합니다. 시스템 헬스 체크는 장비의 상태를 모니터링하고, 오류 발생 시 자동으로 복구하는 기능을 제공합니다.
4.  **FortiGate Firmware 버전 확인:** FortiGate의 Firmware 버전을 최신 버전으로 업데이트합니다. 최신 버전의 Firmware는 버그 수정 및 성능 개선 기능을 제공합니다.

**3. 추론 및 추가 조치**

위의 점검 과정을 통해 다음과 같은 원인을 추론하고 추가 조치를 취할 수 있습니다.

*   **로그 전송 설정 오류:** 로그 전송 설정(대상 서버, 로그 유형, 전송 주기 등)의 오류로 인해 로그가 전송되지 않을 수 있습니다.
*   **네트워크 문제:** FortiGate와 로그 서버 간의 네트워크 연결 문제로 인해 로그가 전송되지 않을 수 있습니다.
*   **방화벽 규칙:** FortiGate의 방화벽 규칙이 로그 서버로 향하는 트래픽을 차단할 수 있습니다.
*   **로그 서버 문제:** 로그 서버에 문제가 발생하여 FortiGate에서 전송된 로그 데이터를 수신하지 못할 수 있습니다. (로그 서버의 CPU, 메모리, 디스크 공간 등을 확인)
*   **FortiGate 설정 오류:** FortiGate의 로그 설정이 잘못되어 로그가 저장되지 않거나 전송되지 않을 수 있습니다.
