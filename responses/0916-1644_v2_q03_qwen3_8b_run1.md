FortiGate에서 로그가 쌓이지 않고 로그 서버로 전송되지 않는 경우, 다음과 같은 점검 순서를 따라 문제를 분석하는 것이 좋습니다.

1. **Log Settings 확인**  
   - 먼저, FortiGate의 로그 설정이 올바르게 구성되었는지 확인해야 합니다.  
   - `Config Log Settings`를 통해 로그 레벨(예: debug, info, warning, error 등)을 확인하고, 로그를 전송할 서버의 IP 주소와 포트 번호, 프로토콜(HTTP/HTTPS), 로그 형식 등을 점검합니다.  
   - 로그 전송에 필요한 포트(예: 80, 443 등)가 방화벽에서 허용되었는지 확인해야 합니다.

2. **Log Forwarding Profile 확인**  
   - `Config Log Forwarding` 명령어로 설정된 로그 전송 프로필을 확인합니다.  
   - 전송할 로그 유형(예: system, network, security 등)과 로그 서버 설정이 올바르게 구성되었는지 확인합니다.  
   - 특히, 로그 서버에 연결할 때 사용하는 ID와 비밀번호, 인증 방법 등이 정확한지 확인해야 합니다.

3. **Log Server 설정 검토**  
   - 로그 서버에 로그를 전송할 때 사용하는 방식(예: HTTPS)에 따라 서버의 SSL 인증서와 관련된 설정이 올바른지 점검합니다.  
   - 예를 들어, FortiGate가 서버의 SSL 인증서를 인증하지 못할 경우, 로그 전송이 실패할 수 있습니다.

4. **Firewall Policy 및 Routing 설정 확인**  
   - 로그 전송 트래픽이 방화벽에서 차단되지 않았는지 확인합니다.  
   - FortiGate의 `Config Firewall Policy`에서 로그 전송 트래픽이 허용되었는지 확인하고, 방화벽 정책에서 해당 트래픽이 제한되지 않았는지 확인해야 합니다.  
   - 네트워크 라우팅 설정이 올바르게 구성되어 로그 전송 트래픽이 목적지 서버에 도달하는지 확인해야 합니다.

5. **Log Forwarding 상태 확인**  
   - `Diagnose Log Forwarding` 명령어를 사용하여 로그 전송 상태를 점검합니다.  
   - 이 명령어는 로그 전송 시 발생한 오류 메시지나 상태 정보를 제공할 수 있습니다.  
   - 예를 들어, `diagnose log forwarding list` 명령어로 전송 중인 로그 전송 프로필을 확인하고, `diagnose log forwarding status` 명령어로 전송 상태를 확인할 수 있습니다.

6. **Syslog 서버에 로그 수신 여부 확인**  
   - 로그 서버에서 로그가 수신되는지 확인하기 위해, 로그 서버에 접속하여 로그 파일을 검토하거나 로그 관리 도구를 사용해 실시간으로 로그를 확인합니다.  
   - 로그가 수신되지 않으면, 전송 오류가 발생했음을 의미할 수 있습니다.

7. **Firmware 및 Config Backup 확인**  
   - 로그 전송 기능이 정상적으로 작동하지 않는 경우, 최신 버전의 Firmware를 확인하고, 구형 버전에 문제가 있는지 점검합니다.  
   - 또한, 구성을 백업하여 복원 후 다시 시도해 보는 것도 고려할 수 있습니다.

위 점검 순서에 따라 문제를 체계적으로 확인하면, FortiGate에서 로그 전송이 정상적으로 이루어지도록 할 수 있습니다. 확실하지 않은 명령어나 설정값은 추측하지 않고, 명확한 정보가 없으면 "모르겠습니다"라고 대답합니다.
