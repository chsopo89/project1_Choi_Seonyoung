FortiGate의 Virtual IP(VIP)로 제공하던 웹 서비스가 중단된 경우, 주요 확인 항목과 점검 순서를 다음과 같이 정리합니다. **확실하지 않은 명령어나 설정값은 추측하지 않으며, 모른다고 명시합니다.**

---

### **1. 웹 서비스의 상태 및 설정 확인**
- **웹 서버 자체 상태**: 서버에서 `systemctl status [웹 서버 서비스 이름]` 또는 `netstat -tuln` 명령어로 웹 서비스가 실행 중인지, 특정 포트(예: 80/443)에서 리스닝 중인지 확인하세요.  
  - 예: Apache는 `apachectl status`, Nginx는 `nginx -t`로 구성 검증.  
  - 서버가 정상적으로 실행 중이고 포트를 열고 있다면, **포트 충돌 또는 네트워크 설정 문제**가 가능합니다.

- **웹 서버의 리스닝 IP/포트**:  
  - `ss -tuln` 또는 `netstat -tuln` 명령어로 웹 서버가 특정 IP(예: `192.168.1.100`) 또는 포트(예: 8080)에 바인딩 중인지 확인하세요.  
  - VIP가 제공하는 IP(예: `203.0.113.42`)가 웹 서버의 리스닝 IP와 일치하는지 확인해야 합니다.  
  - 예: VIP가 `203.0.113.42`이라면, 웹 서버가 해당 IP에서만 리스닝하는 경우, NAT/포트포워딩 설정이 제대로 적용되지 않았을 수 있습니다.

---

### **2. FortiGate의 VIP 및 정책 확인**
- **VIP IP 및 포트 설정**:  
  - `config firewall vip` 명령어로 VIP의 IP 주소, 포트, 인터페이스 설정을 점검하세요.  
  - 예: `get vip` 명령어로 VIP 정보를 확인합니다.  
  - VIP가 제공하는 IP(예: `203.0.113.42`)가 외부 IP인지 내부 IP인지 명확히 확인해야 합니다.  
  - 예: VIP가 외부 IP일 경우, 서버는 해당 IP가 아니라 **내부 IP(예: `192.168.1.100`)**로 리스닝하는 경우, NAT 설정이 필요할 수 있습니다.

- **정책(Static Route/Policy) 확인**:  
  - `config firewall policy` 명령어로 정책의 대상 IP, 포트, 방향(ingress/egress)을 점검하세요.  
  - 예: `get policy` 명령어로 정책의 대상 IP가 VIP IP(예: `203.0.113.42`)인지 확인합니다.  
  - 정책이 **VIP IP에 대한 허용**을 설정했는지, **서버의 내부 IP에 대한 허용**을 설정했는지 확인해야 합니다.  
  - 예: 정책이 VIP IP를 허용하지만, 서버가 내부 IP만 리스닝하는 경우, 포트포워딩이 필요할 수 있습니다.

---

### **3. 네트워크 연결 및 NAT 설정 확인**
- **NAT 설정 점검**:  
  - `config firewall nat` 명령어로 SNAT/DNAT 설정을 확인하세요.  
  - 예: 외부 클라이언트가 VIP IP(203.0.113.42)로 요청하면, FortiGate가 해당 요청을 내부 서버 IP(192.168.1.100)로 라우팅할 수 있도록 SNAT/DNAT 설정이 필요한 경우, 이 설정이 올바르게 구성되었는지 확인해야 합니다.  
  - 예: `dnat6` 또는 `dnat` 명령어로 VIP IP를 내부 서버 IP로 매핑하는 설정이 있는지 점검.

- **인터페이스 설정**:  
  - `config system interface` 명령어로 VIP가 결합된 인터페이스(예: `port1`)의 IP 주소, 서브넷, 상태를 확인하세요.  
  - VIP가 해당 인터페이스에 할당되어 있고, 인터페이스가 활성화된 상태인지 확인해야 합니다.

---

### **4. 서버 방화벽 및 애플리케이션 로그 확인**
- **서버 방화벽 규칙**:  
  - 서버의 방화벽(예: iptables, ufw, firewall-cmd)에서 **FortiGate의 NAT된 소스 IP**가 허용되었는지 확인하세요.  
  - 예: 클라이언트가 VIP IP로 요청하면, FortiGate가 해당 요청을 내부 서버 IP로 라우팅하고, **서버 방화벽이 이 트래픽을 차단**할 수 있습니다.  
  - `iptables -L -n -v` 또는 `ufw status` 명령어로 서버 방화벽 규칙을 점검.

- **웹 서버 로그**:  
  - 웹 서버의 액세스 로그(예: `/var/log/apache2/access.log`)와 오류 로그(예: `/var/log/apache2/error.log`)를 확인하여 **외부 클라이언트의 요청이 도달했는지** 파악하세요.  
  - 로그에 요청이 기록되지 않으면, **NAT 설정** 또는 **서버 방화벽**이 문제일 가능성이 높습니다.

---

### **5. FortiGate 시스템 로그 및 트래픽 분석**
- **시스템 로그**:  
  - `diag sys view log` 또는 `get system event` 명령어로 FortiGate의 시스템 로그를 확인하여 **VIP 관련 오류**나 **트래픽 차단** 메시지를 확인합니다.  
  - 예: "No matching policy" 또는 "Connection denied" 메시지가 있는지 확인.

- **트래픽 감사**:  
  - `diag sys top` 또는 `diag debug flow show` 명령어로 트래픽이 어떻게 처리되는지 추적합니다.  
  - VIP IP로 들어오는 트래픽이 **FortiGate에서 어떤 처리를 받는지** 파악하여 정책 또는 NAT 설정을 확인합니다.

---

### **6. 외부 클라이언트 테스트**
- **외부 클라이언트로 테스트**:  
  - 외부에서 VIP IP(예: `203.0.113.42`)에 요청을 보내면 **클라이언트의 토큰/브라우저에서 어떤 오류가 발생하는지** 확인합니다.  
  - 예: 403 Forbidden, 503 Service Unavailable, 또는 시간 초과가 발생하는지 확인.

- **패킷 트래픽 분석**:  
  - Wireshark 또는 tcpdump로 트래픽을 캡처하여 **FortiGate에서 트래픽이 어떻게 처리되는지** 확인합니다.  
  - 예: 요청이 정책에 매칭되지 않거나, NAT 설정이 잘못되었는지 확인.

---

### **요약 점검 순서**
1. **웹 서버의 리스닝 IP/포트** 확인 → 서버가 VIP IP/포트에 리스닝 중인지.  
2. **FortiGate VIP 및 정책 설정** 확인 → VIP IP/포트가 올바르게 설정되었는지, 정책이 허용했는지.  
3. **NAT 설정 점검** → SNAT/DNAT가 올바르게 구성되었는지.  
4. **서버 방화벽 및 애플리케이션 로그** 확인 → 트래픽이 차단되지 않았는지.  
5. **FortiGate 시스템 로그 및 트래픽 감사** → 오류 메시지 또는 트래픽 처리 방식 확인.  
6. **외부 클라이언트 테스트** → 실제 네트워크 환경에서 문제가 있는지 파악.

이 점검을 통해 **서버 방화벽 규칙**, **NAT 설정**, 또는 **웹 서버의 리스닝 IP/포트** 문제가 원인일 가능성이 큽니다.
